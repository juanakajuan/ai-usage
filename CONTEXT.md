# AI Usage

AI Usage helps a person understand the monetary value of their local artificial intelligence tool usage over meaningful time periods.

## Language

**AI Coding Agent Usage**:
Token usage attributed to local AI coding agent activity on this machine.
_Avoid_: session data, logs

**Codex Usage**:
Token usage attributed to local Codex activity on this machine.
_Avoid_: generic usage, session data, logs

**Pi Usage**:
Token usage attributed to local Pi Coding Agent activity on this machine.
_Avoid_: generic usage, session data, logs

**OpenCode Usage**:
Token usage attributed to local OpenCode activity on this machine.
_Avoid_: generic usage, session data, logs

**AI Coding Agent Session**:
A single local AI coding agent work session whose usage can be grouped, priced, and displayed after source-specific parsing.
_Avoid_: Codex session when the source may be Pi or OpenCode, conversation, request, run

**Usage Source**:
The authoritative location from which usage data is read.
_Avoid_: import, export, provider

**Usage Source Inventory**:
The set of readable local artifacts discovered for one AI Usage run after applying default discovery or a Custom Usage Source.
_Avoid_: source list, scan result, provider registry

**Incomplete Usage**:
Usage that cannot be priced accurately because required local token or pricing data is missing.
_Avoid_: estimated usage, unknown usage

**Historical Cost**:
The monetary value of usage calculated with the price that applied when the usage occurred.
_Avoid_: current cost, current-price equivalent

**Reporting Period**:
A local-calendar time range used to group usage for review.
_Avoid_: window, bucket, interval

**Usage Summary**:
A cost-first view of usage over reporting periods with token counts as supporting detail.
_Avoid_: dashboard, token audit, report

**Input Tokens**:
All tokens sent to a model as part of an AI coding agent request, including cached and non-cached input.
_Avoid_: prompt tokens

**Output Tokens**:
Tokens generated by a model in response to an AI coding agent request.
_Avoid_: completion tokens

**Reasoning Output Tokens**:
Output tokens used for model reasoning when the AI coding agent reports them separately.
_Avoid_: hidden output, reasoning tokens

**Cache Read Tokens**:
Previously cached tokens reused by a model for an AI coding agent request.
_Avoid_: cached input tokens

**Cache Write Tokens**:
Tokens written into a reusable cache by a model for an AI coding agent request.
_Avoid_: cache creation tokens

**Non-Cached Input Tokens**:
Input tokens that were not read from a model cache.
_Avoid_: fresh tokens, billable input tokens

**Total Tokens**:
The source-reported total token count for AI Coding Agent Usage, or the sum of input and output tokens when no source total is available.
_Avoid_: tokens

**Codex Session**:
A source-specific Codex work session whose totals come from the Final Token Snapshot before becoming an AI Coding Agent Session.
_Avoid_: AI coding agent session when the source-specific Codex rules matter, conversation, request, run

**Codex Session File**:
A local Codex JSONL file under the Codex sessions directory.
_Avoid_: transcript, history file, log file

**Codex Sessions Directory**:
The local directory tree where Codex stores session files.
_Avoid_: history, log directory, cache directory

**Session Start Time**:
The local time when an AI Coding Agent Session began.
_Avoid_: file time, last token time

**Session Name**:
A source-recorded short label for an AI coding agent session when the tool stores one.
_Avoid_: prompt summary, inferred title

**Active Session**:
A local AI coding agent session that has token data but no observed completion record yet.
_Avoid_: incomplete usage, failed session

**Token Snapshot**:
A point-in-time Codex record of cumulative and latest token usage for a session.
_Avoid_: token event, usage row

**Final Token Snapshot**:
The last usable token snapshot in a Codex session file.
_Avoid_: summed snapshots, latest row

**Model**:
The exact model name recorded in local AI coding agent usage data.
_Avoid_: model family, provider model, normalized model

**Model Configuration**:
Source-recorded details about how a Model was run, such as reasoning effort or thinking level.
_Avoid_: inferred mode, guessed capability tier

**Compact Model Display**:
A Session Detail rendering that combines the exact Model with available Model Configuration.
_Avoid_: normalized model name, pricing key

**Price Schedule**:
The dated set of token prices used to calculate historical cost for a model.
_Avoid_: rate card, pricing table

**Effective Price Schedule**:
The price schedule whose date range covers the time assigned to usage.
_Avoid_: current price, latest price

**Price Catalog**:
A local versioned collection of price schedules used by the app.
_Avoid_: live pricing, pricing service

**Unpriced Usage**:
Usage with known tokens that cannot be assigned a historical cost because no effective price schedule matches.
_Avoid_: free usage, zero cost

**United States Dollar Cost**:
Historical cost expressed in United States dollars.
_Avoid_: converted cost, local currency cost

**Partial Cost**:
The known historical cost for a reporting period that also contains incomplete usage.
_Avoid_: estimated total, warning-only total

**Derived Summary**:
A usage summary recalculated from local AI coding agent usage data rather than stored as an independent record.
_Avoid_: cached usage, usage database

**Current Source State**:
The AI coding agent usage data available on disk at the time AI Usage is run.
_Avoid_: preserved history, archived usage

**Missing Usage Source**:
A state where no readable local AI coding agent Usage Source can be found.
_Avoid_: zero usage, empty usage

**Zero Usage**:
A state where a readable usage source exists but contains no usage for the reporting period.
_Avoid_: missing data, not found

**Custom Usage Source**:
A user-provided local path that replaces automatic usage source detection for a run.
_Avoid_: import path, configured database

**Run Option**:
A command-line value that changes how a single AI Usage run reads or displays usage.
_Avoid_: preference, setting, configuration file

**Headline Periods**:
The daily, weekly, monthly, and all-time reporting periods shown together in the main usage summary.
_Avoid_: tabs, views

**Session Detail**:
A selected reporting period's newest-first list of AI coding agent sessions with agent label, time, model, price schedule summary, cost status, and token totals.
_Avoid_: raw log, request explorer

**Reload**:
A user action that rereads the current usage source and recalculates derived summaries.
_Avoid_: refresh cache, sync

**Matte Box Palette**:
A terminal color direction based on the local Omarchy matte-box theme: near-black background, warm beige foreground, muted teal accent, and subdued supporting status colors.
_Avoid_: generic monochrome, bright dashboard colors

**Theme-Aware Colors**:
Terminal colors that follow the current terminal theme when available and fall back to the Matte Box palette when needed.
_Avoid_: hardcoded colors, unmanaged colors

**Period Cost Change**:
A compact comparison between a Headline Period's known United States Dollar Cost and the previous matching Reporting Period.
_Avoid_: trend bar, chart, graph, visualization

**All-Time Detail**:
A month-first breakdown of all available AI Coding Agent Usage.
_Avoid_: complete session list, ungrouped history

**JSON Output**:
A non-interactive machine-readable usage summary emitted for a single run.
_Avoid_: export, report file, CSV

**Offline Usage**:
Operation that reads only local AI coding agent data and bundled app data without network access.
_Avoid_: synced usage, live pricing, update check

**Parse Problem**:
A local AI coding agent usage record that cannot be read as valid usage data.
_Avoid_: crash, corrupt app state

**Data Quality Notice**:
A visible indication that some source data could not be included in a derived summary.
_Avoid_: hidden warning, fatal error

**Unknown Source Format**:
A local AI coding agent usage record whose structure is not recognized by AI Usage.
_Avoid_: unsupported app version, bad session

**Data Quality Detail**:
An expanded view of source records skipped or partially excluded from derived summaries.
_Avoid_: main screen warning, debug log

**Redacted Path**:
A local file path whose sensitive home-directory prefix has been replaced for sharing.
_Avoid_: hidden path, anonymized data

**Project Context**:
The local project name or path associated with an AI Coding Agent Session when it helps distinguish usage.
_Avoid_: prompt text, conversation text

**Prompt Content**:
User or assistant message text from AI coding agent activity.
_Avoid_: project context, session metadata

**Project Name**:
The final directory name used as the compact display form of project context.
_Avoid_: full path, repository slug

**Cost Display**:
The human-readable rendering of historical cost after precise calculation.
_Avoid_: rounded source value, approximate spend

**Output Schema Version**:
A version marker included in JSON output so downstream readers know how to interpret the structure.
_Avoid_: app version, price catalog version

## Relationships

- **AI Coding Agent Usage** is read from a **Usage Source Inventory** in the first version.
- A **Usage Source Inventory** is built from default local AI coding agent locations, or from exactly one **Custom Usage Source** when provided.
- A **Custom Usage Source** replaces default discovery for that run; no default or sibling usage sources are added.
- **Incomplete Usage** must remain distinguishable from fully priceable usage.
- **Historical Cost** can only be shown when both usage data and applicable historical pricing are known.
- **Reporting Periods** use the local machine timezone, calendar days, Monday-start weeks, and calendar months.
- A **Usage Summary** emphasizes **Historical Cost** before token counts.
- **Input Tokens** includes **Cache Read Tokens** and **Non-Cached Input Tokens** when those subsets are known.
- **Total Tokens** must not double count **Cache Read Tokens** as separate from **Input Tokens**.
- Missing token categories must preserve available token data and can make **Historical Cost** incomplete.
- **AI Coding Agent Usage** includes **Codex Usage**, **Pi Usage**, and **OpenCode Usage** when their local session files are readable.
- **AI Coding Agent Usage** is aggregated primarily by **AI Coding Agent Session** after source-specific parsing.
- **Codex Usage** contributes **Codex Sessions** to the shared **AI Coding Agent Session** set.
- A **Codex Session** may contain lower-level usage records, but those are supporting detail rather than the primary reporting unit.
- A **Codex Session File** is the default local representation of a **Codex Session**.
- The default **Codex Sessions Directory** is the local Codex sessions tree under the user's Codex home directory.
- An **AI Coding Agent Session** belongs to reporting periods by **Session Start Time**.
- A **Codex Session** uses the **Final Token Snapshot** for its token totals rather than summing token snapshots.
- **Pi Usage** and **OpenCode Usage** totals are summed from assistant-message usage entries before becoming **AI Coding Agent Sessions** because they record per-response usage rather than Codex-style cumulative token snapshots.
- **Non-Cached Input Tokens** can be derived from **Input Tokens** minus **Cache Read Tokens** when both are known.
- **Historical Cost** requires a **Model** that maps unambiguously to a **Price Schedule**.
- **Historical Cost** uses the **Effective Price Schedule** for the session start time.
- **Unpriced Usage** is a form of **Incomplete Usage**.
- **Reasoning Output Tokens** are preserved as detail and priced as **Output Tokens** unless a price schedule distinguishes them.
- A **Model** must preserve the exact name recorded by the AI coding agent.
- **Model Configuration** is shown only when the source records it; AI Usage must not infer thinking level from the Model name.
- **Codex Usage** for `gpt-5.5` uses the Fast mode **Price Schedule** because the local Codex source does not expose whether Fast mode was active and the current user assumes Fast mode by default.
- **Compact Model Display** may append Model Configuration to the Model in Session Detail without changing the Model used for pricing.
- **Price Schedules** come from the app's local **Price Catalog** in the first version.
- **Historical Cost** is displayed as **United States Dollar Cost** in the first version.
- A **Reporting Period** with both priceable usage and **Incomplete Usage** shows **Partial Cost** with a visible incomplete marker.
- A **Usage Summary** is a **Derived Summary** in the first version.
- **AI Coding Agent Usage** is not copied into a separate app-owned usage database in the first version.
- **Derived Summaries** reflect the **Current Source State** and do not preserve usage that has disappeared from the usage source.
- **Missing Usage Source** must be distinguishable from **Zero Usage**.
- A **Custom Usage Source** can be used when automatic usage source detection is not appropriate.
- The first version uses **Run Options** rather than persistent app configuration.
- A **Usage Summary** shows all **Headline Periods** together.
- A **Usage Summary** includes **Session Detail** for the selected reporting period.
- **Reload** updates the **Usage Summary** from the **Current Source State**.
- The terminal interface uses the **Matte Box Palette** for its visual direction.
- The terminal interface prefers **Theme-Aware Colors** over hardcoded colors.
- **Period Cost Changes** support the numeric **Usage Summary** without replacing headline totals.
- The all-time **Headline Period** uses **All-Time Detail** rather than a flat session list.
- **JSON Output** represents the same derived usage information as the terminal **Usage Summary**.
- The first version supports **Offline Usage** only.
- **Parse Problems** produce partial derived results with a **Data Quality Notice**.
- **Unknown Source Format** is treated as a **Parse Problem** and skipped with available path and reason detail.
- **Data Quality Notices** summarize problems on the main screen, while **Data Quality Detail** shows paths and reasons.
- **JSON Output** includes source paths by default and can use **Redacted Paths** when requested.
- **Session Detail** includes the AI coding agent label for each session.
- **Session Detail** may include **Session Name** when the source records one.
- **Session Detail** may include **Project Context** but excludes **Prompt Content** in the first version.
- AI Usage must not infer **Session Name** from **Prompt Content**.
- **Session Detail** shows **Project Name** in terminal lists and full project paths only in **JSON Output**.
- **Cost Display** rounds only the displayed value; calculations keep higher precision until aggregation is complete.
- **JSON Output** includes an **Output Schema Version**.
- **Active Sessions** are included using their latest available token snapshot and marked as active.

## Example Dialogue

> **Developer:** "Should we estimate missing token counts from message length?"
> **Domain expert:** "No. If local AI coding agent data does not contain enough information, show it as **Incomplete Usage**."
>
> **Developer:** "Should last month's usage be repriced with today's model prices?"
> **Domain expert:** "No. Show **Historical Cost** when the price for that usage date is known."
>
> **Developer:** "Which date decides the price for a session?"
> **Domain expert:** "Use the **Effective Price Schedule** for the **Session Start Time**."
>
> **Developer:** "Should a late-night session be grouped by UTC day?"
> **Domain expert:** "No. Group **Reporting Periods** by the local machine timezone."
>
> **Developer:** "If a session starts before midnight and ends after midnight, where does it belong?"
> **Domain expert:** "Assign the **AI Coding Agent Session** to reporting periods by **Session Start Time**."
>
> **Developer:** "Should the first screen lead with tokens or dollars?"
> **Domain expert:** "Lead a **Usage Summary** with **Historical Cost**, then show token counts as supporting detail."
>
> **Developer:** "Can we price all tokens with one rate?"
> **Domain expert:** "No. Preserve **Input Tokens**, **Output Tokens**, **Cache Read Tokens**, and **Cache Write Tokens** because they can have different prices."
>
> **Developer:** "Should we sum every token count row in a Codex session file?"
> **Domain expert:** "No. Use the **Final Token Snapshot** so repeated cumulative snapshots are not double counted."
>
> **Developer:** "Should reasoning tokens disappear inside output totals?"
> **Domain expert:** "No. Preserve **Reasoning Output Tokens** as detail, but price them as **Output Tokens** unless pricing distinguishes them."
>
> **Developer:** "Should the report list every model call first?"
> **Domain expert:** "No. Aggregate by **AI Coding Agent Session** first, with individual calls as optional detail later."
>
> **Developer:** "Can we normalize similar model names before pricing?"
> **Domain expert:** "No. Preserve the recorded **Model** and only price it when it maps unambiguously to a **Price Schedule**."
>
> **Developer:** "Should totals update automatically when live provider prices change?"
> **Domain expert:** "No. Use the local **Price Catalog** so historical calculations are reproducible."
>
> **Developer:** "If a model has tokens but no matching price, is that zero cost?"
> **Domain expert:** "No. Treat it as **Unpriced Usage** and mark the cost incomplete."
>
> **Developer:** "Should the app convert historical costs into my local currency?"
> **Domain expert:** "No. Show **United States Dollar Cost** in the first version."
>
> **Developer:** "If a month has three priced sessions and one unpriced session, should we hide the dollar total?"
> **Domain expert:** "No. Show the **Partial Cost** with an incomplete marker."
>
> **Developer:** "Should AI Usage keep its own usage database?"
> **Domain expert:** "No. The first version should produce a **Derived Summary** from local AI coding agent data each time it runs."
>
> **Developer:** "If old local AI coding agent data is deleted, should AI Usage keep showing the old totals?"
> **Domain expert:** "No. The summary reflects the **Current Source State**."
>
> **Developer:** "If we cannot find local AI coding agent data, should the total be zero?"
> **Domain expert:** "No. Show **Missing Usage Source**, not **Zero Usage**."
>
> **Developer:** "Should v1 only support the default Codex path?"
> **Domain expert:** "No. Allow a **Custom Usage Source** for runs that need a different local path."
>
> **Developer:** "Where does automatic source detection look first?"
> **Domain expert:** "Use the default **Codex Sessions Directory** under the local Codex home directory."
>
> **Developer:** "Should AI Usage remember my preferred source path in its own config file?"
> **Domain expert:** "No. Use **Run Options** in the first version."
>
> **Developer:** "Should daily, weekly, monthly, and all-time totals live behind tabs?"
> **Domain expert:** "No. Show the **Headline Periods** together in the main summary."
>
> **Developer:** "How much drill-down does v1 need?"
> **Domain expert:** "Show **Session Detail** for the selected period, not every raw usage event."
>
> **Developer:** "Should the app update from disk automatically only?"
> **Domain expert:** "No. Provide **Reload** so the user can reread the current source on demand."
>
> **Developer:** "What does minimalist but modern mean visually?"
> **Domain expert:** "Use the **Matte Box Palette** with restrained spacing and status markers that still work without color."
>
> **Developer:** "Should the app hardcode the Matte Box colors?"
> **Domain expert:** "No. Prefer **Theme-Aware Colors** with a **Matte Box Palette** fallback."
>
> **Developer:** "Should v1 be numbers only?"
> **Domain expert:** "No. Use **Period Cost Changes** as compact supporting context while keeping headline totals numeric."
>
> **Developer:** "Should all-time detail list every Codex session?"
> **Domain expert:** "No. Use **All-Time Detail** so long histories are grouped by month first."
>
> **Developer:** "Should v1 only be interactive?"
> **Domain expert:** "No. Provide **JSON Output** for scripts and verification."
>
> **Developer:** "Should the app fetch latest prices when it starts?"
> **Domain expert:** "No. The first version supports **Offline Usage** only."
>
> **Developer:** "Should one unreadable Codex record stop the whole app?"
> **Domain expert:** "No. Show partial results with a **Data Quality Notice** for the **Parse Problem**."
>
> **Developer:** "Should unknown future Codex records be guessed?"
> **Domain expert:** "No. Treat **Unknown Source Format** as a **Parse Problem** and show what was skipped when possible."
>
> **Developer:** "Should file paths for skipped records be visible on the main screen?"
> **Domain expert:** "No. Keep the main **Data Quality Notice** concise and put paths in **Data Quality Detail**."
>
> **Developer:** "Should JSON output hide local file paths?"
> **Domain expert:** "No. Include paths by default for audit use, with **Redacted Paths** available for sharing."
>
> **Developer:** "Should session detail show conversation prompts?"
> **Domain expert:** "No. Use **Project Context** for attribution when useful, but exclude **Prompt Content**."
>
> **Developer:** "Should the session list show full project paths?"
> **Domain expert:** "No. Show **Project Name** in terminal lists and reserve full paths for **JSON Output**."
>
> **Developer:** "Should an unfinished local session be ignored?"
> **Domain expert:** "No. Include **Active Sessions** with the latest available token snapshot and mark them active."
>
> **Developer:** "Should costs be rounded before they are aggregated?"
> **Domain expert:** "No. Keep precision through calculation and round only the **Cost Display**."
>
> **Developer:** "How do scripts know which JSON shape they received?"
> **Domain expert:** "Include an **Output Schema Version** in every **JSON Output**."

## Flagged Ambiguities

- "usage" can mean all artificial intelligence tools or local coding agents; resolved: the first version tracks local **AI Coding Agent Usage**.
- "cost" can mean historical spend or current-price equivalent; resolved: canonical cost means **Historical Cost**.
- "effective pricing" can mean usage-date pricing or latest known pricing; resolved: use the **Effective Price Schedule** for the **Session Start Time**.
- "daily, weekly, monthly" can mean rolling windows or calendar ranges; resolved: they are local-calendar **Reporting Periods**.
- "session date" can mean start time, end time, or file date; resolved: use **Session Start Time**.
- "summary" could mean a token audit or spend dashboard; resolved: **Usage Summary** is cost-first.
- "tokens" can hide differently priced categories; resolved: use explicit token category terms and derive **Total Tokens** only from known categories.
- "input tokens" can include cached and non-cached input; resolved: use **Non-Cached Input Tokens** when separating input pricing.
- "token rows" can mean cumulative snapshots or additive records; resolved: use the **Final Token Snapshot** for session totals.
- "session" can mean a source-specific work session, a conversation, or a single model request; resolved: **AI Coding Agent Session** is the primary shared usage aggregation unit, while **Codex Session** names source-specific Codex rules.
- "model" can mean a family or an exact recorded identifier; resolved: **Model** means the exact recorded name.
- "pricing" can mean live provider pricing or bundled app pricing; resolved: v1 uses a local **Price Catalog**.
- "unpriced" can mean free or unknown cost; resolved: **Unpriced Usage** is incomplete, not zero.
- "money's worth" can imply converted local currency; resolved: v1 shows **United States Dollar Cost** only.
- "incomplete total" can mean no total or a guessed total; resolved: show **Partial Cost** with a visible incomplete marker.
- "stored usage" can mean Codex-owned source data or an app-owned copy; resolved: v1 uses **Derived Summary** and does not maintain an app-owned usage database.
- "history" can mean preserved app history or currently available source data; resolved: v1 reflects **Current Source State** only.
- "empty" can mean no source or no usage; resolved: **Missing Usage Source** and **Zero Usage** are separate states.
- "source path" can mean auto-detected data or an explicit override; resolved: **Custom Usage Source** is an explicit local path for a run.
- "local AI coding agent data" can mean history, logs, cache, sessions, or app databases; resolved: the default source is a **Usage Source Inventory** built from local coding agent artifacts.
- "configuration" can mean run-specific flags or persistent app preferences; resolved: v1 uses **Run Options** only.
- "daily, weekly, monthly, and all-time" can mean separate screens or one summary; resolved: they are **Headline Periods** shown together.
- "details" can mean session audit or raw log browsing; resolved: v1 shows **Session Detail**.
- "refresh" can mean network sync or rereading local data; resolved: **Reload** rereads the current usage source from disk.
- "modern minimalist" can mean generic monochrome or a specific system palette; resolved: use the **Matte Box Palette**.
- "theme colors" can mean live terminal colors or fixed hex values; resolved: use **Theme-Aware Colors** with a Matte Box fallback.
- "chart" can mean a large graph or compact context; resolved: v1 uses **Period Cost Changes** rather than charts.
- "all-time detail" can mean a complete session list or a grouped history; resolved: **All-Time Detail** is month-first.
- "export" can mean machine-readable output or document reporting; resolved: v1 supports **JSON Output** only.
- "offline" can mean no telemetry or no network at all; resolved: **Offline Usage** means no network access in v1.
- "parse failure" can mean a fatal app failure or partial source failure; resolved: **Parse Problems** produce **Data Quality Notices**.
- "unknown format" can mean inferred data or excluded data; resolved: **Unknown Source Format** is skipped rather than guessed.
- "data quality warning" can mean a concise status or full debug information; resolved: main screen shows **Data Quality Notice**, expanded view shows **Data Quality Detail**.
- "redaction" can mean omitting paths or replacing sensitive prefixes; resolved: **Redacted Path** preserves audit usefulness while hiding home-directory-sensitive prefixes.
- "session context" can mean project metadata or prompt contents; resolved: v1 may show **Project Context** but excludes **Prompt Content**.
- "project" can mean a full local path or compact display name; resolved: **Project Name** is used in compact lists.
- "rounded cost" can mean rounded calculation or rounded display; resolved: **Cost Display** rounds after precise aggregation.
- "JSON version" can mean app release or output contract; resolved: **Output Schema Version** identifies the JSON structure.
- "active session" can mean incomplete data or an ongoing session; resolved: **Active Session** is included with a visible active marker.
